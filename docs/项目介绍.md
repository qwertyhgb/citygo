# CityGo 项目介绍

> 本地生活服务平台后端 —— 一个覆盖「用户 → 商家 → 店铺 → 商品 → 购物车 → 订单 → 支付 → 营销 → 评价 → 搜索 → 秒杀」完整业务链路的 Spring Boot 单体应用。
>
> 🎓 **定位**：以真实互联网业务场景为蓝本的学习项目（非生产）。以单体架构起步、按业务域清晰分包，是系统学习 **Spring Boot 4 + Redis / RabbitMQ / Elasticsearch** 等常用中间件的实战载体，后续可按业务边界平滑演进为微服务。

---

## 一、项目概述

### 1.1 项目背景

CityGo 参考美团等本地生活平台的经典业务模型，把一条完整的电商交易链路搬到后端工程里：从用户注册登录开始，商家入驻开店、上架商品，用户浏览搜索、加购下单、支付评价，中间穿插优惠券营销、订单超时关单、秒杀抢购等高并发场景。

它不是一个 CRUD Demo，而是**用工程化的方式把每个真实业务场景的关键难点都做扎实**：

- 登录态怎么做才能"登出即失效"？
- 下单怎么防止库存超卖？
- 订单超时关单怎么实现得优雅（不依赖插件）？
- 秒杀怎么抗住高并发（一人一单 + 不超卖 + 削峰）？
- 数据库和搜索引擎之间的数据一致性怎么保证？

每个问题在项目里都有对应的落地方案，并配有 [15 篇学习笔记](notes/) 做代码走读与面试点讲解。

## 三、系统架构

### 3.1 总体架构

单体 Spring Boot 应用，按业务领域分包，典型请求链路：

```
Client
  │  (Bearer JWT)
  ▼
Spring Security 过滤链
  ├─ JwtAuthenticationFilter ── 校验 JWT + Redis 登录态 ──▶ SecurityContext(userId, roles)
  ▼
@Controller / @RestController
  ▼
@Service ──(事务)──▶ MyBatis-Plus Mapper ──▶ MySQL
  │
  ├─ Redis（登录态 / 缓存 / 锁 / 限流 / 幂等 / 秒杀预扣）
  ├─ RabbitTemplate ──▶ RabbitMQ（异步解耦、削峰、延迟）
  └─ ElasticsearchOperations ──▶ ES（搜索索引，afterCommit 双写同步）
```

### 3.2 分层与分包

每个业务包遵循统一分层：`controller → service → mapper → entity`，外加 `dto`（入参）/ `vo`（出参）隔离边界：

```
com.citygo
├── CityGoApplication.java    # 启动入口（@MapperScan("com.citygo.**.mapper")）
├── common/                   # Result / ErrorCode / 全局异常 / 分布式锁 / 限流切面 / 幂等切面 / 分页
├── config/                   # MyBatis-Plus / Redis Cache / OpenAPI 配置
├── auth/                     # 认证、JWT、SecurityConfig、角色权限
├── user/                     # 用户
├── merchant/  shop/          # 商家店铺（管理端 / 浏览端）
├── product/  category/       # 商品 / 分类（含秒杀配置）
├── cart/  address/           # 购物车 / 收货地址
├── order/                    # 订单、支付、状态机、商家端订单
├── coupon/                   # 优惠券、用户券
├── review/                   # 评价、店铺评价
├── search/                   # ES 索引初始化 / 文档 / 仓储 / 服务 / 同步
├── seckill/                  # 秒杀（控制器 / 服务 / MQ 消费者）
└── mq/                       # RabbitMQ 配置与消费者
```

### 3.3 基础设施依赖

开发 / 测试环境连接本机 Docker 容器中的 MySQL、Redis、RabbitMQ（官方镜像、无延迟插件）、Elasticsearch（带 IK 分词）。所有连接信息可通过环境变量覆盖，生产配置只保留占位骨架，敏感信息不硬编码。

## 四、核心业务链路深度解析

### 4.1 认证授权链路（JWT + Redis 无状态）

1. 注册：BCrypt 加密密码，默认绑定 `USER` 角色。
2. 登录：校验密码（不走 `DaoAuthenticationProvider`），成功后用 jjwt 0.13 新 API 签发 JWT，并把 `citygo:login:token:{token} → userId:roleCodes` 写入 Redis（TTL = token 有效期），返回 token + 用户信息。
3. 请求鉴权：`JwtAuthenticationFilter` 在 `UsernamePasswordAuthenticationFilter` **之前**执行，解析 JWT + 校验 Redis 登录态，二者均通过才写入 `SecurityContext`（principal 为 userId）。
4. 登出：删除 Redis key，**即时失效**——这是纯 JWT（无状态）方案做不到的，也是本项目选"JWT + Redis"组合的核心原因。
5. RBAC：`SecurityConfig` 按路径 + 方法精确配置放行 / 鉴权，未认证 401、无权限 403（框架层直接拼 JSON）。

安全细节：登录失败统一返回「用户名或密码错误」防撞库；公开读接口（店铺 / 商品 / 分类 / 可领券 / 搜索 / ping）放行，写接口与「我的」类接口强制登录。

### 4.2 下单链路（事务 + 快照 + CAS）

```
下单请求
  ├─ 校验商品 / 地址 / 购物车项
  ├─ 商品与收货信息【快照】固化（历史订单永远可正确展示）
  ├─ 库存 CAS 扣减：UPDATE ... WHERE stock >= 需求数量（防超卖）
  ├─ 创建订单（状态 10 待支付）+ 订单项 + 支付记录
  ├─ 用券校验与核销（若有）
  └─ 事务提交后：
      ├─ 发延迟消息（消息级 TTL）→ 到期自动关单
      ├─ 发库存预警消息（order.created）
      └─ 同步 ES / 清理缓存
```

状态机离散取值：`10 待支付 → 20 已支付 → 30 已接单 → 40 配送中 → 50 已完成`，另有 `60 已取消 / 70 退款中 / 80 已退款`。状态流转全部用**条件更新**（`UPDATE ... WHERE status = ?`）保证并发安全。

### 4.3 订单超时关单（TTL + 死信队列，零插件）

为什么不用延迟插件：本地 RabbitMQ 是官方镜像且禁止装插件，因此使用 RabbitMQ 原生能力：

```
下单 → 发送消息级 TTL 消息到延迟交换机
  → 延迟队列（消息独立计时，规避队列级 TTL 的"队头阻塞"）
  → 到期消息自动进入死信交换机（DLX）
  → 按 routing-key=timeout 进入超时队列
  → OrderTimeoutConsumer：状态机校验（10→60）→ 取消订单 + 回补库存
```

### 4.4 秒杀链路（高并发三板斧）

`SeckillServiceImpl` 的五层防线：

1. **Redis `SETNX` 一人一单查重**：TTL 覆盖活动期，规避 DB 查重导致的并发穿透。
2. **Redis `DECR` 库存预扣**：内存扣减，防止超卖与行锁竞争。
3. **Lua 脚本原子执行**：`查重 + 扣减 + 用户占位` 一个脚本完成，消除并发间隙与多次网络往返。
4. **MQ 异步削峰落库**：预扣成功后投递 `seckill.order` 消息，消费者异步创建订单。
5. **DB 条件更新兜底**：消费者端再次一人一单复查 + 条件更新扣减，极端场景回补 Redis。

热点配置（秒杀价 / 时段 / 库存）预热进 Redis，抢购请求零查库。

### 4.5 支付成功广播（Fanout 解耦）

- `payment.success` 为 **Fanout 交换机**：绑定的所有队列都会收到消息 → 一次支付、多渠道通知（用户 + 商家）。
- 后续新增通知渠道（短信 / 推送）只需**加一条队列绑定，无需改动支付代码**——广播解耦的核心价值。

### 4.6 搜索双写一致性（afterCommit）

- 索引 `citygo_shop` / `citygo_product`，启动时 `ESIndexInitializer` 自动建索引 + 写映射（IK 分析器 + geo_point）。
- **为什么必须 afterCommit**：ES 不参与本地 MySQL 事务。若在事务内同步，事务回滚会留下"幽灵文档"；若 ES 写失败又会拖垮本地事务。用 `TransactionSynchronizationManager.afterCommit` 保证 **MySQL 提交成功后才同步 ES**，ES 失败只记 ERROR 不阻断主流程。
- 一致性取舍：主库为准，允许索引短暂不一致；生产可升级为 MQ / Canal 异步同步。

### 4.7 评价与评分联动

- 一单一评（同一订单只能评价一次），提交评价后事务内更新店铺 `score`（加权平均）与 `review_count`（冗余字段，避免每次 count 查询）。
- 商家可回复评价；店铺详情 / 列表直接读取冗余评分，热门排序依赖该字段。

## 五、数据库设计

### 5.1 表结构（14 张）

| 分组 | 表 |
| --- | --- |
| 用户 / 权限 | `user`、`role`、`user_role` |
| 商家 / 店铺 | `merchant`、`shop` |
| 商品 / 分类 | `category`、`product` |
| 订单 / 支付 | `orders`、`order_item`、`payment` |
| 营销 | `coupon`、`user_coupon` |
| 评价 / 地址 | `review`、`address` |

秒杀能力以 `product` 扩展字段（`seckill_price / seckill_stock / seckill_start / seckill_end`）与 `orders.source`（1 普通 / 2 秒杀）实现，**未新增独立表**。

### 5.2 关键设计决策

| 决策 | 说明 |
| --- | --- |
| 无物理外键 | 逻辑外键 + 索引，写入性能更好，解耦迁移 |
| 雪花 ID 主键 | MyBatis-Plus 默认，全局唯一、趋势递增 |
| 全局逻辑删除 | `deleted` 字段（0/1），数据可恢复 |
| 快照机制 | 订单固化商品名/单价、收货人信息，历史订单永远正确展示 |
| 金额用 DECIMAL | 避免浮点误差 |
| 状态离散取值 | 10→80 递增枚举，便于排序与扩展 |
| 冗余字段 | `shop.score` / `review_count`、商品销量，读多写少场景用空间换时间 |

### 5.3 迁移管理（Flyway）

- 脚本位于 `src/main/resources/db/migration/`，启动时按版本号顺序自动执行，记录写入 `flyway_schema_history`。
- V1 建表 + 索引 → V2 角色种子 → V3 分类数据 → V4 示例券模板 → V5 秒杀字段 → V6 修正用户券唯一键 + 店铺评价数冗余字段。
- **铁律**：版本只增不回退；已发布的迁移文件严禁修改，变更必须新增更高版本脚本。

> 完整 ER 图、字段 / 索引说明与 8 条设计决策见 [database-design.md](database-design.md)。

## 六、工程实践与亮点

### 6.1 统一返回 & 全局异常

- `Result<T>`：固定 `{code, message, data}`，**HTTP 状态码恒为 200**，业务成败由 `code` 承载（`200` 成功，其余见 `ErrorCode`）。
- `GlobalExceptionHandler`（`@RestControllerAdvice`）：`BizException`、参数校验、`AuthorizationDeniedException`、404 统一收敛；业务异常记 WARN、系统异常记 ERROR 并打堆栈，**绝不向调用方暴露内部细节**。

### 6.2 Redis 多场景应用

| 场景 | 实现 |
| --- | --- |
| 登录态 | `citygo:login:token:{token}`，登出即失效 |
| 缓存 | Spring Cache（JSON 序列化、`缓存名::key` 前缀、默认 TTL 10 分钟），如店铺详情 / 热门商品 |
| 分布式锁 | `SET key uuid EX NX` + Lua 原子解锁（防误删他人锁） |
| 接口限流 | 固定窗口计数器，Lua 原子 `INCR+EXPIRE`，超限抛 429 |
| 防重复提交 | 基于 `X-Request-Id` 的 `SETNX` 幂等，超时抛 409 |
| 秒杀预扣 | `SETNX` 一人一单 + `DECR` 预扣 + Lua 原子脚本 |

### 6.3 消息队列（RabbitMQ）

| 消息流 | 交换机 | 说明 |
| --- | --- | --- |
| 下单 → 库存预警 | Direct `order.created` | 库存 < 阈值写入 `citygo:stock.warn` |
| 支付成功 → 广播 | Fanout `payment.success` | 用户 + 商家队列，新增渠道零改代码 |
| 订单超时 | 消息级 TTL → DLX | 规避队头阻塞，超时消费者状态机 10→60 |
| 秒杀异步下单 | Direct `seckill.order` | 削峰落库 |

消息统一 JSON 序列化（Jackson 3 的 `JacksonJsonMessageConverter`）；消费者重试 2 次后入死信，不无限回队（`default-requeue-rejected: false`）。

### 6.4 安全设计

- BCrypt 密码哈希；JWT 密钥 ≥ 32 字节，生产通过环境变量注入，禁止硬编码。
- 越权校验：店铺 / 商品 / 订单的修改操作均校验归属（当前商家只能操作自己的资源）。
- Actuator 仅暴露 `health,info` 端点。

### 6.5 多环境配置

| Profile | 用途 | 说明 |
| --- | --- | --- |
| `dev`（默认） | 本地开发 | 连本机容器，SQL + debug 日志，Flyway 自动迁移 |
| `test` | 测试 | 与 dev 共用库，压低日志 |
| `prod` | 生产骨架 | 敏感信息全走 `${ENV}`，不硬编码 |

```bash
mvn test                                  # 全部测试
mvn -Dtest=SeckillControllerTest test     # 单个测试类
```

## 八、快速开始

### 前置依赖
JDK 21、Maven 3.9+；本地 Docker 运行 MySQL 8.4、Redis 7、RabbitMQ 3（官方镜像）、Elasticsearch 9（带 IK 分词插件）。

### 1. 初始化数据库与账号
```bash
mysql -u root -p < sql/init_citygo_db.sql   # 仅建库 + 专用账号（citygo / citygo_user）
```
表结构由 Flyway 在应用首次启动时自动创建，无需手动执行迁移脚本。

### 2. 配置连接（可选）
默认连 `localhost` 容器，密码回退 `Citygo@2026`；可用环境变量覆盖：
```bash
export MYSQL_PASSWORD='你的密码'
export MYSQL_HOST=127.0.0.1
# prod 还需：MYSQL_PORT / MYSQL_DATABASE / MYSQL_USERNAME / SERVER_PORT / citygo.jwt.secret
```

### 3. 构建 & 启动
```bash
mvn clean test            # 运行测试（需四个中间件均可用）
mvn spring-boot:run       # 启动（默认 dev，端口 8080）
```
